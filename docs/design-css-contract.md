# AnimeWP の CSS 責務とカスタマイズ契約

これは WordPress の標準ブロック・Global Styles・Font Library を中心とした「汎用の骨格 × 編集可能な世界観」の実装ルールです。新しい部品を増やす前に、既存の利用者設定が子要素で失われないことを優先します。

## 所有権を分ける

| レイヤー | 所有者 | 役割 |
| --- | --- | --- |
| サイト全体の役割 | theme.json と styles/colors/*.json | base / surface / contrast / accent / font families / spacing。色を切り替えても骨格を変えない |
| スタイル候補 | styles/text/*.json と styles/sections/*.json | 英字見出し・ラベル・反転面・ガラスなどを任意に選択 |
| HTMLの骨格 | Core Blocksと templates / patterns / examples | 文章・画像・カラム・リンクをCore属性として保存し編集可能にする |
| テーマCSS | assets/css/animewp.css | 幾何学、装飾、縦書き、レスポンシブ、操作領域。Coreの文字値を子へ再指定しない |
| 互換性 | assets/css/compat.css と defaults.css | 1.xの色・間隔を維持しつつ、新しい明示設定を優先 |
| 任意の演出 | animewp-blocks | 動画、装飾、回転、モーション。本文の保存形式は壊さない |

## カスケードと個別設定の契約

設計上の優先順位は **明示的なブロック設定 ＞ 選択されたスタイル／Global Styles ＞ コンポーネントの初期値 ＞ 継承** です。ただしCSSの実際の優先順位は specificity・読み込み順・important に依存するので、実ブラウザーテストで確認します。

1. Core Paragraph / Heading が書体・サイズ・太さ・行高・字間・色を所有する。通常の子リンクは文字の値を継承し、リンクの下線・タップ領域だけテーマが担当する。
2. Core Columnsの保存された幅、Core Groupのブロック間隔、Font Libraryで追加した書体は利用者が変えられる。初期レイアウトを維持するために important 付きCSSで固定しない。
3. 装飾の色はパレットの役割slugを使う。暗い面では色の不透明度だけで補助ラベルを薄くせず、ユーザーの明示した文字色を受け継ぐ。
4. 縦書き・画像マスク・回転・クリッピングと、編集できるタイポグラフィ・色・余白を分離する。前者は装飾、後者は標準のブロック設定が権威を持つ。
5. コンポーネントのクラスへスコープを限定する。初期のタイポグラフィは :where() で弱く設定する。変更後も編集画面と公開側で同じ結果にする。

## 独立部品と親要素

39個の部品は、登録済みのパターンのブロックツリーから抽出します。複製したHTMLを別途管理しません。Coreだけの33部品は任意プラグインなしでも使え、追加ブロックが必要な6部品はプラグインがある場合だけ登録します。

**持ち運ぶのは、その部品の骨格と最小限の初期密度です。** 親の配色やフォントを勝手に固定しません。

- フッターの著作権・法務の部品は、単体でも小さい文字とコンパクトな間隔が初期値。個別のGroup / Paragraphの編集値を優先する。
- サイトマップの Paragraph がタイポグラフィを所有する。リンクは継承する。新しいフッターは横書き、以前保存されたフッターは以前の縦書き表示を維持する。
- フッターのカラム比率はCore Columnsが保存した値を尊重する。70%/30%などの手動幅を初期装飾CSSで上書きしない。
- 短い縦書き見出しは自動バランス折り返しを使わず、781px以下で横書きに戻る。任意の書体指定を固定フォントで奪わない。
- Video Cardの枠線と影はフレーム、書体と文字設定はカード本体。タイトルはカードの行高を継承する。ラベルは補助メタデータとして小さなサイズとコンパクトな行高を独立して保持し、色と書体は継承する。

## テストと保存互換性

- PHP実統合テスト：公開slugの固定リストと実際に登録された全slugを照合し、1件でも欠けたら失敗。任意プラグインをスキップしたWP-CLIでもCoreだけの33部品を検査する。
- ブラウザー：保存ブロック内の段落文字設定がリンクへ届く、カラム幅・個別Gapが効く、Video Cardの文字設定が届く、縦書きの文字が重ならないことを検査する。
- 旧形式：過去のslug、既定の静的保存HTML、データベースは変更しない。既に保存したフッターの縦横指定を保つ。
- スクリーンショットを確認し、CI成功と実機保証を区別する。全部品×全配色×全設定が無条件に検証済みとは言わない。

## 境界

これは「全子要素が独立したWordPressブロックになる」という意味ではありません。Video Cardのラベルとタイトルは内部RichTextで、個別のParagraphと同じ設定パネルを持つわけではありません。独立した編集が必要ならCore GroupとParagraphで作るか、保存互換性を保った新しいUI設計が必要です。

サイトエディターに保存済みのテンプレートや、ページへ挿入済みの通常パターンの構造は、テーマ更新だけでは書き換えません。共通CSSの修正と新しいパターン内容の再挿入は別です。
