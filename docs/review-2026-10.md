# AnimeWP v2 全体レビューと次の作業

レビュー日: 2026-10-08 JST（2026-10-07 UTC）。対象は `nanophate/animewp` の main、コミット `4a79dd19e7d7bb05ea26c084494367ca2df9b3c3`、ツリー `a1a155f55f6d789f9224faf05095b265708f62d4` です。PR #2 と #7 のマージ後を取得しました。

## 対象と結論

対象時点の追跡ファイル254個をすべて取得し、各 blob とツリーが GitHub の内容に一致することを確認しました。テーマ、独自8ブロック、Motion、生成見本、認可・入力処理、保存互換性、ビルド・ZIP、翻訳、CI、依存監査、既存PR、Release、文書を横断して見直しています。

既存 main の CI は成功していましたが、監査エラーの誤成功、見本から失われる Motion 設定、古いメニューリンク、公開側の操作不具合、ビルドや ZIP の検査漏れを再現しました。この変更で修正し、失敗する条件を検査へ追加しています。WP更新配信はまだ計画段階であり、ソースをマージするだけでは既存サイトへの更新通知は始まりません。

全ファイルを対象にしたレビューと、すべての実環境での動作保証は異なります。実ブラウザー、実サイト、更新インストール、外部サービスとの組み合わせは、下の残作業へ明記しています。

## 検証内容と再実行

修正前のコードに対して、監査の不正結果・範囲漏れ、フロントエンドの異常動作、必須配布ファイルの欠落、無印ライブラリーの混入を再現しています。修正後に単に成功するだけでなく、対象の異常を失敗として検出することを確認します。

| 検査 | 範囲 |
| --- | --- |
| 監査 wrapper の回帰 | 21件。別経路、期限、不正JSON、異常終了、offline / omit の固定など |
| フロントエンド回帰 | 28件。DOM・イベント・タイマー・CSS契約・dialog fallback |
| jsdom harness | 6件。通常/デバッグの例外・構文エラー・UTF-8エンコード等。helper は24と30の双方で確認 |
| ビルド方針 | 6件。自作＋WP外部依存、無印ライブラリー、結合、遅延、未使用、比較ソース |
| ZIP 構成 | 3つの回帰テストに加え、49の必須項目をそれぞれ欠落させる検査 |
| WordPress 結果集計 | 6件。正常、空、不正、PHP失敗、wp-env 終了失敗、実 wrapper の伝播 |
| 既存検査 | provider 22件、lint、デザイントークン、資産、色コントラスト、構文、静的検査、ZIP再現性 |
| 保存互換性 | WP 6.6 / 7.1 のエディタースクリプト、保存文書7件・生成ケース3,627件と標準7種×4 Motion 設定 |
| 実 WordPress CI | PHP 8.0 / 8.3 構文。WP `6.6-branch` / PHP 8.0 と WP `7.1-branch` / PHP 8.3 の checker・機能・HTTP試験 |

ローカル環境には PHP と Docker がないため、その実行結果は GitHub Actions で確認します。jsdom の成功は実ブラウザーでの表示・読み上げ・実映像再生の検証ではありません。WordPress の2系統は枝を追う検査であり、7.1については取得時の開発版を含みます。実行時点の正確な版と結果は PR の Checks・ログを参照してください。

通常の開発環境での再実行:

```sh
npm ci
npm ci --prefix tests/serialization
python3 scripts/validate.py
npm run env:start
npm run test:security
npm run test:wp
ANIMEWP_WP_DIR="$(sh tests/serialization/fetch-wordpress.sh 6.6-branch)" node tests/serialization/compare.js --base-ref origin/main
ANIMEWP_WP_DIR="$(sh tests/serialization/fetch-wordpress.sh 7.1-branch)" node tests/serialization/compare.js --base-ref origin/main
ANIMEWP_WP_DIR="$(sh tests/serialization/fetch-wordpress.sh 6.6-branch)" node scripts/build-examples.js --check
python3 scripts/package.py
```

最後に `artifacts/releases` で `sha256sum --check SHA256SUMS` を実行します。比較対象は、変更前のコミットを含むローカル ref が必要です。WordPress 統合試験は使い捨ての tests 環境専用です。

## セキュリティの現状

今回の npm 11.16.0 によるオンライン監査では、配布用の実行時依存と serialization 側の advisory は0件でした。ルート開発ツールには critical 2件・high 4件の直接 advisory があり、PR #7 で確認済みの6件だけを引き続き受容します。moderate 8件・low 1件もログへ出ます。これらは advisory の件数であり、npm が集計する影響パッケージ数とは異なります。

受容対象は `@wordpress/env` / `@wordpress/scripts` 経由の開発専用依存に限ります。期限は6件とも **2027-01-08（UTCの日付）** です。修正では受容する ID・理由・期限を増やさず、適用範囲を狭くしました。「監査成功」は「脆弱性が完全に0件」を意味しません。

設定済みの定期処理は、毎日04:23 JSTの依存監査、毎週月曜04:17 JSTのDependabot、毎週月曜04:37 JSTのソース・WordPress検査です。GitHub側の開始遅延はあり得ます。これは本リポジトリの検査であり、利用者の稼働中 WordPress 本体や別プラグインを自動検査するものではありません。

### D: 製品として追加したい場合の機能

これらは現行v2を直すための必須条件ではありません。`overhaul-plan.md` に残っていた計画です。必要性と順序を決めてから別変更にします。

- 利用者が名前を付けて編集・再利用する Motion プリセット。

- 製品名と最低WordPress版の再検討。既存インストール後のフォルダー名変更は別の移行設計が必要。

## 次に着手する順序

まずこの修正PRのCIと実ブラウザー・実ZIP更新を確認し、配布版番号を決めます。その後、公開配布先 → Release生成 → JSON → WP側updater → 次版への更新E2E の順に進めると、公開先のない更新通知や、インストールできないZIPを先に案内する状態を避けられます。既知 advisory の期限対応と稼働サイトの保守は、この順序と並行して続けます。
