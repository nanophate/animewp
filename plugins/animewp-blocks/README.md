# AnimeWP Blocks

バージョン2.0.2。任意のcompanion plugin。WordPress 6.6以上・PHP 8.0以上を対象にした、対応するGutenberg環境で使える静的ブロック8種類と、標準ブロックにも適用できるモーションを提供します。配布ZIPはビルド済みのため、導入時のビルド操作や追加パッケージは不要です。動きの初期値はオフで、白・黒・灰色を初期値とし、任意色・サイトの色見本・色の役割から自由に設定できます。名前付き配色スキンは含みません。

従来の4ブロック（装飾パネル・回転テキスト・画像と本文・動画ボタン）はCoreのグラデーション設定に対応します。パネルではCoreの文字揃えも選べます。指定値はブロックのラッパーに保存され、パネル・文字グループ・画像と本文は標準グループへの変換時にも色・グラデーション・文字揃えを引き継ぎます。

## 導入

`animewp-blocks` フォルダーを `wp-content/plugins/` に置き、管理画面の「プラグイン」で有効化してください。「AnimeWP」でブロックを検索できます。テーマだけでもサイトを運用でき、このプラグインだけを別テーマで利用することもできます。

有効化・停止・削除で、投稿、固定ページ、利用者が保存した設定、メニュー、リライトルールを変更しません。独自テーブル、独自投稿タイプ、外部フォント、解析処理、初期コンテンツの生成はありません。選択・入力した画像や動画の配信元には、通常のメディア表示としてブラウザーから接続します。

2.0.1以降はWordPressサーバーがGitHubの固定JSONへ更新を問い合わせ、更新確認用キャッシュを保存します。公開配布が始まればWordPress標準画面から更新でき、ZIPのSHA-256を検証します。旧版からは一度だけ手動ZIPで置き換えてください。このプラグインかanimewpテーマの一方が有効なら、2.0.1以降へ導入済みの両コンポーネントを確認できます。両方とも無効な場合は手動更新です。GitHubトークンはサイトに保存せず、WordPressの自動更新設定も変更しません。更新処理固有の診断文は英語です。

## ブロック

### 組み合わせて使う3つの部品

それぞれ単独で使え、組み合わせると予告映像の一覧、キービジュアル、キャラクター紹介などを作れます。見た目は初期状態では控えめで、必要な演出だけを設定でオンにします。どれも保存HTMLに内容が残るため、プラグインを停止しても動画へのリンク・ポスター・文章は表示されます。

| ブロック | 単独での役割 | 主な設定 |
| --- | --- | --- |
| `animewp/carousel` — カルーセル | 中に入れたブロックを1枚ずつのスライドにします。動画カード、カバー、画像、カラムなど何でも入れられます。 | スライドの幅（前後をのぞかせる）、スライド／フェード、表示中以外を控えめに、前へ・次へ（丸いアイコン／文字／矢印線／なし）、ドット／番号／サムネイル、自動切り替え（一時停止ボタン付き） |
| `animewp/video-card` — 動画カード | ポスター・再生ボタン・ラベル・タイトル。押すとYouTube・Vimeo・動画ファイルをプレーヤー画面で開きます。 | 動画URL、ポスター（メディアライブラリー、またはYouTubeのサムネイルを取り込み）、縦横比、角丸・枠線・影（スタイル → ブロックで全カード一括も可） |
| `animewp/backdrop` — 背景レイヤー | 置いた区画（グループなど）の背景になります。 | 画像（焦点）、ループ動画ファイル、表示中のスライド・カードのポスターに追従、表示中の動画を無音で再生、ぼかし、かぶせる色と濃さ |

例：グループ（全幅）の中に「背景レイヤー（追従）」「見出し」「カルーセル（幅64%・控えめ）＋動画カード」を置くと、表示中の映像に合わせて背景が切り替わる映像コーナーになります。カルーセル（フェード・サムネイル）の各スライドにカラム（画像＋紹介文）を入れるとキャラクター紹介になります。

YouTubeのサムネイルは、編集者が「YouTubeのサムネイルを取り込む」を押したときだけ、サーバーが一度取得してメディアライブラリーに保存します。訪問者のブラウザーは再生を押すまで動画サービスに接続しません（背景レイヤーで「表示中の動画を無音で再生」を選んだ場合を除きます）。

### モーション（対応する標準・独自ブロック）

段落・見出し・グループ・カラム・画像などの対応ブロックに、右側の設定「モーション」が加わります。背景レイヤーやテンプレートパーツなど、一部のブロックは対象外です。

| 項目 | 内容 |
| --- | --- |
| 登場 | フェードイン／下から浮かぶ／行頭・行末からスライド／ズームイン／ぼかしから鮮明に／ワイプ／1文字ずつ。画面に入ったときに1回再生します。 |
| 適用先 | 「このブロック」または「中のブロックに1つずつ順に」。グループに設定すると、中の見出し・本文・ボタンが順番に現れます。 |
| 待ち時間・長さ・間隔 | 0ならサイト共通の値（`--wp--custom--animewp--motion--*`）を使います。 |
| ポインターを合わせたとき | 浮き上がる／画像を拡大／光る。 |
| 動き続ける | 浮遊／ゆれる／脈打つ。装飾向け。 |
| パララックス | スクロールに対して遅く・速く動きます。 |
| 下にスクロールした後 | 隠す／表示する／コンパクトにする。AnimeWPの「キービジュアルを見せるヘッダー」では「メニューを展開する」も選べます。 |
| 切り替えのきっかけ | 「スクロール距離」または「キービジュアルを通過した後」。距離はブロックごとに0〜10,000pxで指定でき、既存設定の初期値は64pxです。キービジュアルは本文内の最初の表示中のカバー／カルーセルを使います。 |
| ヘッダーの見た目 | AnimeWPの「キービジュアルを見せるヘッダー」で、背景の不透明度（0〜100%）・ぼかし（0〜24px）・最小の高さ（48〜120px）を設定します。文字やリンク自体は透過しません。 |

設定はブロックのコメントにだけ保存し、表示時にクラス・CSS変数・切り替え条件のdata属性として加えます。保存HTMLは変わらないため、プラグインを停止してもブロックは壊れず、動きなしで表示されます。端末で動きを減らす設定をした訪問者には、アニメーションを行わず、スクロール後のナビゲーションは引き続き使えるようにします。登場アニメーションのスクリプトが読み込めない場合は3秒後に表示し、スクロール制御を開始できない場合は最初から内容を表示します。

「キービジュアルを見せるヘッダー」は、最初は右上の小さなメニューボタンだけを置き、カバーを通過するとナビゲーションを展開する設定が初期値です。ロゴ・サイトタイトルは含まず、ひとつの標準ナビゲーションを両方の状態で使います。開いたメニューには不透明な背景を付けます。カバーが見つからないページでもリンクを利用でき、メニュー操作中やリンクにキーボードのフォーカスがある間は表示を保ちます。設定はヘッダー内の外側のグループを選択して行い、表示タイミングはサイトのプレビューで確認してください。

### `animewp/decoration` — 装飾

区画内の好きな位置に置く形（円・輪・花びら・きらめき・ドット・波）または画像。位置・大きさ・回転・不透明度・重なり（後ろ／前）・重ね方を設定でき、形は文字色で色を変えられます。モーションの「浮遊」「パララックス」と組み合わせて使います。

### `animewp/panel` — 装飾パネル

内側に標準ブロックを自由に追加できます。画像、リンク、段落、見出し、カラム、動画などを混在できます。2・3・5列や各列の幅は標準の「カラム」で設定してください。

背景色・文字色・内外余白・ブロック間隔・文字サイズ・行高は標準スタイル設定を使います。テーマが標準UIを制限する場合は、そのテーマの設定が優先されます。標準背景とグローバルスタイルの背景は常にブロック本体に残ります。「装飾背景レイヤーを追加」を明示的にオンにすると、その上に任意色の色面を重ね、境界（波形／斜め）・装飾背景だけの回転・傾斜・不透明度を設定できます。回転は色面を回し、傾斜は色面を斜めにゆがめます。どちらも本文の角度を変えません。装飾面の外側や半透明部分には標準背景が見えます。パネル全体の回転、角丸、パネルの影、文字の影、短い見出しの帯は別途設定できます。標準の影を指定した場合は、その値が追加の影プリセットに優先します。

「折り返す各行に帯」は行ごとに背景を複製し、「余白つきの一枚パネル」は見出し全体を一枚で囲みます。縦書きは任意の短い見出しだけに適用します。40文字を超える見出し、本文、幅781px以下の表示では横書きです。傾斜や回転は隣接要素との間隔を見ながら設定してください。装飾背景の境界・不透明度・傾斜は追加レイヤーにだけ作用し、標準背景そのものを切り抜きません。背景全体を透過した波形にする場合は、標準背景を透明にして装飾レイヤーの色を指定してください。

「パネル全体の回転」は従来どおり、背景とすべての内側ブロックをまとめて回転します。子ブロックの0度は親の回転を打ち消しません。1.1.0では入れ子のパネルが親の装飾変数を誤って引き継がないよう修正しました。たとえば親が4度・子が0度の場合、子にさらに4度が加わることはありませんが、子を含む親全体は4度回転します。各パネルの角度、角丸、帯、背景色面、不透明度、間隔、影の設定はそれぞれのパネルに限定されます。通常の文字色や文字サイズなど、標準CSSの継承は利用できます。

### `animewp/text-group` — 回転テキスト

段落・見出し・リスト・標準グループなどをまとめ、そのグループの角度を調整します。内側には標準ブロックを自由に追加できます。別の文字グループや外側に置いた段落の角度は変わりません。文字列の一部分を選択して回転する機能ではありません。

1. パネルの「パネル全体の回転」を0度にします。
2. パネル内で「回転テキスト」を追加し、その内側に傾けたい段落や見出しを置きます。既存ブロックはリスト表示から移動できます。
3. リスト表示や編集画面下の階層から「回転テキスト」を選び、「この文字グループの回転」を設定します。範囲は−8〜8度で、0度は水平です。
4. 水平にしたい段落は、同じパネル内で文字グループの外に置きます。別角度の文章を追加する場合は、もう一つ文字グループを並べて、それぞれに角度を設定します。

たとえば、パネル内に「文字グループA：−3度」「通常の段落」「文字グループB：4度」を並べると、通常の段落は水平で、AとBだけが各角度になります。背景だけも傾けたい場合は、パネルの装飾背景レイヤーをオンにして「装飾背景だけの回転」を指定します。

「この文字グループの回転」は幅782px以上、「モバイルの回転」は幅781px以下に適用します。モバイルは読みやすさのため初期値0度で、必要なら−8〜8度で個別に設定できます。文字グループを入れ子にしても回転変数は継承しません。ただし親のパネルや文字グループ自体が回転していれば、内側もその幾何学的な回転を受けます。親に対する角度を設定するため、子を0度にしても親の回転を相殺しません。

回転は表示だけの変更で、読む順・Tab順は変えません。回転した要素のために前後の間隔が自動で広がることはないため、標準の外側余白と内側余白で、折り返し・隣の文章との重なり・フォーカス表示を確認してください。背景・文字色・文字サイズ・行高・ブロック間隔も標準スタイル設定を利用します。編集画面と公開画面で同じ構造とCSSを使用し、画面幅に応じて同じ角度を適用します。

挿入メニューのパターン「AnimeWP Blocks」には「背景と傾いた見出し・水平本文」と「角度の違う2つの文字グループ」を用意しています。前者は背景−2度・見出し−3度・本文0度、後者は文字グループ−3度と4度で、どちらも親パネルは0度です。見本の文章を置き換えて使えます。パターンは利用者が挿入したときだけ本文に入り、有効化だけで投稿を作成・変更しません。

### `animewp/media` — 画像と本文

標準の「画像」と、標準ブロックを自由に追加できる「グループ」を内包します。画像の代替テキスト・リンク・キャプションは標準画像ブロックで編集します。

「読む順」は内側のブロックを実際に並べ替え、保存HTMLの順序、読み上げ順、Tab順、モバイルの表示順を一致させます。デスクトップの左右配置は見た目の構図だけを変更します。幅781px以下では常に保存DOMの順で縦に並びます。画面幅変更時のJavaScriptによるDOM移動はありません。

画像の切り抜きは初期状態ではオフです。有効にするとデスクトップとモバイルの高さ・焦点を個別に設定できます。重ね配置はデスクトップだけに適用します。内側の標準グループで背景色や余白を指定し、画像と文字・キャプションの重なりやコントラストを確認してください。

### `animewp/video` — 動画ボタン

動画ファイル、YouTube、公開Vimeoに対応します。ファイルはメディアライブラリまたはURLから指定します。認証付き配信や限定公開Vimeoは元リンクで案内してください。他社ブロックや標準core/embed全体へ同意機能を追加するものではありません。

ファイル動画は通常のvideo・字幕・説明・元リンクを保存します。字幕はこのページと同じ配信元に置くのが初期設定です。「匿名CORS」を選ぶとvideoにcrossorigin="anonymous"を付けます。別配信元の動画と字幕は両方ともAccess-Control-Allow-Originを返す必要があります。認証付きCORSは対象外です。動画と字幕が互いに同じ配信元であっても、ページと別の配信元ならCORS設定が必要です。

YouTubeとVimeoは保存HTMLにiframeや外部サムネイルを含めません。「外部サービスへ接続」と明記されたボタンを押した時だけプレーヤーを作り、閉じると除去します。YouTubeはプライバシー強化URL、Vimeoはdnt指定を使いますが、接続後の通信は発生します。サービス側で字幕を用意し、ブロック内に説明・文字起こし・元リンクを残してください。ポスターはサイト内パスだけを保存し、外部画像を自動取得しません。同一配信元の絶対URLは入力・source切替時に相対パスへ正規化します。公開画面で対応URLとサイト内ポスターがある場合は、JavaScript初期化後に限りポスター画像と再生ボタンを16:9の枠へ配置します。この枠は保存HTMLに加えません。画像や有効な動画URLがない場合は、保存済みの画像・リンク表示を保ちます。

HTMLDialogElement対応ブラウザーではネイティブモーダル、Escape、フォーカス復帰を使います。ファイル動画は自動再生せず、閉じると一時停止します。外部iframeは自動再生指定を送りません。JavaScript無効・未対応・停止時はファイル動画または元リンクで利用できます。

匿名CORS付き動画を標準ブロックへ変換すると、video部分はCORS属性を保持するためカスタムHTMLになります。WordPress 6.6と7系のHTML保存形式に対応します。変換後も動画・字幕・説明・リンクを残します。プラグイン停止後の保存済み表示は残りますが、制限された権限でHTMLを再保存するとCoreのフィルターがcrossoriginを除去する場合があります。停止前に検証してください。

## 停止・別の形式への移行

保存形式は静的HTMLと `InnerBlocks.Content` です。サーバーで動的に本文を生成しません。停止後も表示側の本文・標準メディアは残り、独自装飾と動画のダイアログ機能が外れます。

編集を続ける場合は、停止前にブロックの変換メニューを使う方法を推奨します。

- パネル → 標準グループ。短い見出しも標準見出しへ変換します。
- 文字グループ → 標準グループ。内側の文章・標準グループ・リンク・ブロック順を保持し、回転を外します。
- 画像と本文 → 標準グループ。画像の設定・キャプション・本文・保存順を保つ最も確実な移行です。
- 画像と本文 → 標準「メディアとテキスト」も選択できます。本文のグループ設定を残し、画像キャプションは本文側の段落へ移します。モバイル焦点・独自の読む順・重ね配置は標準ブロック側の動作へ変わります。画像の特殊なリンクや拡大表示などは再確認してください。
- 動画ボタン → 標準グループ内の標準動画・字幕・説明段落・追加ブロック。ダイアログ装飾は外れます。

停止済みの場合は、一時的に再有効化して上記変換を行うか、未対応ブロックのメニューから保存内容をカスタムHTMLとして保持できます（メニュー名は環境により異なります）。投稿を複製して確認すると移行を比較できます。アンインストールで保存内容は削除しません。

## CSSカスタムプロパティ

各ブロックのCSSは `.wp-block-animewp-*` の範囲へ限定しています。標準ブロック向けモーションは、表示時に付ける `.animewp-motion` とその子要素へ適用します。独自のグローバル変数・HTMLクラス・data属性・スクリプト／スタイルhandleは `animewp` 名前空間に限定しています。PHPは `Animewp\Blocks` 名前空間です。ブロック設定で指定した値は、対応するカスタムプロパティのインライン指定に反映されます。

テーマやサイト側のCSSから、次のプロパティを任意の値で調整できます。パネルと文字グループは各ルートで変数を初期化するため、変更したいブロック本体のセレクターを指定してください。親要素や `:root` から独自装飾変数を継承させる指定は使いません。プラグインには生CSS入力・JavaScript入力・HTML直接実行のUIを設けていません。

| 対象 | プロパティ |
| --- | --- |
| 装飾背景レイヤー | `--animewp-panel-backdrop-background`、`--animewp-panel-opacity`、`--animewp-panel-skew`、`--animewp-panel-backdrop-rotation`（レイヤーがオンの場合に適用） |
| パネル角丸 | `--animewp-panel-radius` |
| パネル全体 | `--animewp-panel-rotation`、`--animewp-panel-box-shadow`、`--animewp-panel-text-shadow`、`--animewp-panel-gap` |
| 見出しの帯 | `--animewp-panel-highlight`、`--animewp-panel-highlight-padding` |
| 文字グループ | `--animewp-text-group-rotation`、`--animewp-text-group-mobile-rotation`、`--animewp-text-group-gap` |
| 画像と本文 | `--animewp-media-image-width`、`--animewp-media-gap`、`--animewp-media-height`、`--animewp-media-mobile-height`、`--animewp-media-focus`、`--animewp-media-mobile-focus` |
| 動画ボタン | `--animewp-video-button-color`、`--animewp-video-button-background`、`--animewp-video-button-radius` |
| ダイアログ | `--animewp-video-dialog-color`、`--animewp-video-dialog-background`、`--animewp-video-dialog-padding` |

## 実装と検証

各 `src/blocks/<名前>/block.json` が現行ブロックの属性・型・初期値・enumの単一の定義元です。ビルドで `build/blocks/<名前>/` へコピーされ、PHPはそこからサーバー登録し、エディター側も同じ `block.json` を読み込んで登録します。ブロックごとにedit／save／旧形式（deprecated）／変換を分けたファイルで構成し、保存HTMLを作る関数は編集画面と共有します。旧保存形式の読込用定義は、当時の属性・対応機能・保存処理を別途固定して保持しています。`apiVersion: 3`、メタデータの `style` と `editorStyle` により、投稿編集画面とサイトエディターのiframeにもCSSを渡します。保存時はURL・数値範囲・enum・独自色指定を正規化します。

1.1.0のパネル初期値の修正はCSSで行い、既存の保存構造を維持します。新しい装飾背景の回転は初期値0度では保存スタイルを追加しません。不透明度はWordPressのバージョンに左右されない単位なしの文字列で保存します。1.0.0とWordPress 6.6の組合せで保存された `--animewp-panel-opacity:0.7px` などの旧形式も互換定義で読み込めます。編集して保存すると、同じ不透明度を正しく表示できる `0.7` などの単位なし形式に移行します。旧形式の0には元から単位がなく、100%は従来どおりスタイルを省略します。単位なしで保存された1.0.0のブロックもそのまま受け付けます。

文字グループも静的HTMLと内側の標準ブロックを保存し、停止・削除後も文章やリンクを残します。プラグイン更新・表示・編集画面の読込だけでデータベースを書き換えません。投稿の一括更新、グローバルスタイルへの変更はありません。

保存HTMLの互換性は `tests/serialization/compare.js` で確認します。WordPress本体のエディタースクリプト（6.6と7.1）を使い、基準のgitリビジョンと作業中のビルドで、保存済みフィクスチャー・パターン・数千通りの属性組合せの保存結果、再読込時の妥当性、標準ブロックへの変換結果がすべて一致することを比較します。実WordPressでの保存→再読込・サーバー登録、投稿者権限での保存、エディターiframeの見た目、停止後の表示、ネイティブ変換、キーボード操作、実動画と字幕の再生は、統合環境での確認項目です。1.xではWordPress 6.6/PHP8.0と7.1.2/PHP8.3で新旧保存・変換を検証しました。v2の現在の確認範囲と残作業はリポジトリのdocs/review-2026-10.md、1.xの実測履歴はdocs/verification.mdを参照してください。複数ブラウザー、支援技術、任意テーマの全組合せは未検証です。

## 開発

ソースは `src/`、WordPressが読み込むのは `build/` です。ホストに必要なのはNode.js 24.18以上、npm 11.16以上、Python 3.10以上、Dockerです。PHPとWordPressはDocker（`@wordpress/env`）で動かします。リポジトリのルートで実行します。

```sh
npm ci                                  # ビルド・Lint・Docker環境の道具
npm run env:start                       # localhost:8888 に開発用、localhost:8889 に試験用のWordPress 6.6を起動（wp-env既定の管理者で入れます）
npm start                               # 編集中は自動ビルド
npm run lint:js                         # WordPressのコーディング規約
npm ci --prefix tests/serialization     # 互換性テストの道具（初回のみ）
python3 scripts/validate.py --compare   # ビルド、PHP（Docker）、監査、保存HTML比較
npm run test:wp                         # WordPress統合試験（試験用サイト localhost:8889 で実行。開発用サイトの内容は変えません）
npm run test:security                   # セキュリティ検査（PHPCSのWordPressセキュリティ規則、Plugin Check、Theme Check。試験用サイトで実行）
npm run i18n                            # 翻訳ファイルを再生成（WP-CLIをDockerで実行）
```

画面の文言は英語の原文と、同梱の日本語訳（`languages/`）で表示します。保存HTMLに含まれる「配信元で動画を見る」などの文言は表示言語に関係なく固定です（翻訳すると既存投稿の検証に失敗するため）。

## 1.2の色・互換性

装飾背景と見出しの帯には、任意色、標準の登録済み色見本、surface／accent／contrastの役割を選べます。役割は対応する前景色を使い、明示した文字色を優先します。半透明・傾斜・画像重ね・子ブロックの個別色では利用者がコントラストを確認してください。別テーマで役割トークンがない場合は白黒の代替値になります。すべてのテーマで同一の見た目になる保証はありません。

既存1.0/1.1の既定属性の保存HTMLを維持します。0度はtransform:noneです。明示された非ゼロ回転だけを変形し、既定のfixed子孫を画面基準に保ちます。手書きHTMLで回転変数を0degとして残す場合や、別CSSで変数だけを変更する場合は適用対象になるため、不要な回転指定を外してください。画像ブロックの幅・焦点・高さ・間隔は入れ子ごとに初期化します。
